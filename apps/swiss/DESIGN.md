## 1. 這個 App 是什麼

一次性的單趟旅程現場作戰手冊。服務 2026/07/24–08/08 五人三代家庭的瑞士＋杜拜行程。

- 舊版：repo `wayuanzi-web/st2607`｜v3.12｜密碼閘（密碼不寫進 repo）｜**8/8 封存，旅途中不得改動**
- 新版（本目錄）：travel-suite 沙盒內的 1.0 重建，角色是**旅程模板**——換掉 `data/` 就是下一趟旅行
- 設計語彙：瑞士鐵路風格（SBB 藍白紅 `#1F3864`/`#C8102E`、tabular-nums 時刻表字體、月台看板美學）
- 使用場景：站在月台上、拿著手機、五個人在等你決定 → 單手、大字、高對比、離線可用、maxWidth 520

## 2. 方法論（其他 App 要「一句話參考」的核心資產）

1. **指令而非資訊**。不寫「在 Brig 轉車」，寫「只有8分鐘:下車先看藍色看板找Andermatt月台,5人跟緊不拍照」。每條資訊都可直接執行。
2. **資料驅動**。TRIP 物件＝一次旅行；程式不含旅程知識，換 data 換旅程。
3. **風險上限三條**（RISK3）。太多沒人記得。
4. **逐步導航 NAVSTEP**。key＝行程項目的原文字串，value＝用「→」串連的每一步。全 App 最有價值的資產（104 條）。
5. **餐廳決策最小資料集**：星等＋評論數＋價位帶＋公休＋Google Place ID（一鍵導航）。
6. **中英對照站名**（v3.12 起）：給當地人看、自己認站牌。

## 6. 安全註記

- GitHub Pages＝**全公開**，密碼閘只是禮貌不是保護；repo 內任何資料視同公開
- DOCS 的 Google Drive 連結靠 Drive 權限保護（需登入）；護照效期欄留白、訂位代號已遮——1.0 維持此原則，敏感值只進 localStorage 由使用者自填
- **公開頁面不放可識別個人的資料**（2026-10 定案，適用所有 App）：成員一律用稱謂，App 名稱不帶名字；不放證件、票券這類圖片；不放卡片、證件、訂位號碼的任何片段；健康狀況不指名；不寫職業。這類東西只有兩個去處：**雲端硬碟（要登入才看得到）**，或使用者自己裝置上的 localStorage
- 頁面一律加 `noindex`，不讓搜尋引擎收錄

## 7. 踩過的坑（血淚）

1. `minify:true` 且原始碼未進 repo → **v3.12 原始碼永久遺失**。1.0 鐵則：可讀原始碼與 index.html 一起 commit，minify 可留但必產出對照
2. 打包 entryPoint 指錯檔 → 白屏無錯誤訊息
3. 無 ErrorBoundary → 出錯白屏無法遠端除錯（1.0 必加，含 safe-area、Service Worker、版本浮水印）
4. v3.12 已知 bug（8/2 已診斷）：PlaceChip pk/id 屬性不一致致餐廳卡不顯示；「餐廳用語」按鈕失效；票券圖 1.7.5 起不內建，改由使用者自行上傳或放雲端硬碟（見 §17）
5. LINE 內建瀏覽器開啟會失效 → HELP 保留警告
6. `sw.js` 換版時把網域上「不是自己的」快取全刪 → 同帳號其他 GitHub Pages 網站（skywing、badminton…）的離線快取被連帶刪掉。`wayuanzi-web.github.io` 底下所有網站共用同一個快取空間與 localStorage，只能動自己前綴的東西（快取 `wang-swiss-*`、storage `wang.swiss.*`）。2026-10-04 修正，見 §16
7. 公開網頁不內嵌票券、證件這類圖片：圖就在網頁原始碼裡，密碼閘擋不住。要出示的票券由使用者在 App 內自行上傳（只存自己的裝置），或放雲端硬碟用連結開。見 §6、§17
8. 文字也是公開內容：說明頁、會話、清單、AI 提示詞裡不寫名字與職業，不寫卡片或證件號碼的片段，健康狀況不指名（會話用不指名的「他」）。`test.mjs` 有檢查守著。見 §6、§17

## 14. 1.5.1 — 金鑰不內建（2026-08-03）

**原則**：公開 repo 與公開網頁裡不放任何金鑰。1.5.1 起照這個原則調整。

**做法**
1. `NEARBY_KEY_DEFAULT` 是空字串,程式碼**永不內建金鑰**；金鑰只存使用者本機 `localStorage: wang.swiss.gkey`
2. 「更多→工具→🔑 附近搜尋金鑰」改為必填入口(密碼欄位遮蔽)，未設定時「📍即時附近」顯示引導而非報錯
3. 刪除 build 中間產物 `apps/swiss/app.js`(內含同一份 bundle)
4. **Git 歷史重整**：以無父節點的新 commit 覆蓋 main

**規則(適用所有 App)**：任何憑證一律只存使用者裝置端；repo 內不得出現任何金鑰、token、密碼。公開過的金鑰一律到發行端（Google Cloud）撤銷或重新產生，整理 repo 不等於撤銷。

待辦與後續處理不記在公開 repo，記在使用者的私人紀錄（Claude 專案「0生活」）。

## 16. sw.js 只清自己的快取（2026-10-04，App 版本仍為 1.7.4）

**問題**：`activate` 時刪掉 `caches.keys()` 裡所有不等於目前版本的快取。GitHub Pages 同帳號的網站是同一個網域（`wayuanzi-web.github.io`），快取空間共用，所以 swiss 一換版，別的網站（蒼穹戰翼、羽球訓練手冊）的離線快取就被清空，要等它們下次連線開啟才補回來。

**改動**：只刪名稱以 `wang-swiss-` 開頭、且不是目前版本的快取。`make.mjs` 的樣板與部署層 `swiss/sw.js` 同步修改，兩者內容一致。

**沒動的部分**：`index.html` 沒有重建（App 本身沒變，版本維持 1.7.4、快取名稱維持 `wang-swiss-v1.7.4`）；`make.mjs` 需要的 v1 骨架原始檔路徑在這次的環境不存在，所以沒有跑完整建置，只改 sw.js 這一段。

**驗證**：以本機主機模擬「線上舊版 → 修正版」的更新：修正前，別的網站的快取 2 份被刪 2 份；修正後 2 份都保住，自己的舊快取照樣清掉，更新後離線仍可開啟。`node test.mjs` 修改前後結果相同（44 通過／4 失敗；失敗的 4 項是「今天」落在行程日期之外的 3 項與需要連網的天氣 1 項，與這次修改無關）。

**其他網站**：skywing 同日做了相同修正。family-hub 的 `sw.js` 於 2026-10-05 也改成只清 `familyhub-` 開頭的快取（見 §18）；它另有兩處會影響整個網域的寫法還在（錯誤畫面的「清除本機資料」用 `localStorage.clear()`、`?nosw=1` 會解除所有 service worker 並清掉所有快取），重建 hub 時不要沿用。

## 17. 1.7.5–1.7.8 — 公開內容整理（2026-10-04～06）

**原則**（細節見 §6）：repo 與線上頁面全公開，所以頁面裡不放可識別個人的資料；這類東西放雲端硬碟（要登入）或使用者自己的裝置。

**現在的做法**
1. **票券**：`data/tickets_embedded.js` 是空的（`export default []`），`EmbeddedTickets` 沒有資料時整區不顯示。要出示票券用票券頁的「自行上傳的票券」（照片只存在各自的裝置），或把檔案放雲端硬碟、在 `data/ticket_links.json` 加連結。這趟的通票放在雲端硬碟「00瑞士／07鐵路通票」，1.7.8 起票券頁第一個連結就是它（只有被授權的家人帳號打得開）。
2. **成員**：一律用稱謂 `爸爸／媽媽／孩子A／孩子B／奶奶`（`trip.json` 的 `members`、`extras_v1.json` 的 `passports`、`ticket_links.json`、v1 骨架、各測試腳本）。要換稱謂只改 `data/trip.json` 的 `members`（連同 `extras_v1.json` 的 `passports`）。
3. **App 名稱**：1.7.7 起是「家族旅遊通」（`trip.json` 的 `name`、`make.mjs` 的網頁標題、repo 首頁）。
4. **文字**：證件頁、會話、行前清單不寫卡片或證件號碼的片段；會話用不指名的說法（中／德／英三欄一致）。
5. **閘門**：密碼以加鹽的 SHA-256 存放（`tail.jsx` 的 `GATE_SALT`、`GATE_HASH`，內附一個小的同步 `sha256hex`）。閘門只是禮貌，不是保護（§6）。換密碼：
   `node -e "console.log(require('crypto').createHash('sha256').update('wang.swiss.gate:'+'新密碼').digest('hex'))"`，把結果填進 `GATE_HASH` 後重建。
6. **建置**：`make.mjs` 讀 repo 內的 `src-v1-skeleton.tsx.txt`（不再依賴上傳目錄）；之後一律用這一份。
7. **搜尋引擎**：`swiss/index.html` 與 repo 首頁都有 `noindex`。

**`test.mjs` 守著的檢查**：內嵌圖只剩閘門背景照、原始碼沒有明文密碼比對、頁面沒有卡片尾號、病名不指名家人。

**對已在使用的裝置**
- 已過閘門的裝置不受影響。
- 裝置上存的舊身分名稱（`wang.swiss.user`）不在新名單裡時，功能照常；重新過一次閘門就會換成新稱謂。
- 分帳裡以前記的帳照原本存的名字顯示（資料只在各自的裝置），新記的用新稱謂。
- 行前清單的勾選是依順序存的，改字不影響已勾的項目。

**驗證**：`node test.mjs` 45 通過／4 失敗，失敗的 4 項與整理前相同（「今天」不在行程日期內的 3 項、需連網的天氣 1 項）；`audit.mjs`、`probe.mjs`、`verify171.mjs`、`dist174.mjs`、`ui173.mjs`、`hl.mjs` 全數通過。閘門以 jsdom 實測：原密碼可通過、錯誤密碼被擋，`sha256hex` 與 Node 內建結果一致。`swiss/index.html` 約 750 KB。
